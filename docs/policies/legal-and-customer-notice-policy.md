# Legal And Customer Notice Policy

Status: Confirmed

## Purpose

고객에게 고지해야 하는 약관, 개인정보, 배송, 취소, 환불, 공급처 품절 가능성 안내 기준을 정한다.

## Policy Areas

- 이용약관
- 개인정보처리방침
- 배송 정책
- 취소/환불 정책
- 주문 후 품절 가능성 고지
- 상품 상세 고지
- 주문서 고지
- 고객 알림 방식

## Proposed MVP Direction

- 상품 상세와 주문서에서 공급처 품절 가능성을 고지한다.
- 품절 시 해당 배송그룹 주문 금액이 환불된다는 내용을 명확히 표시한다.
- 이용약관, 개인정보처리방침, 배송/환불 정책 페이지를 출시 전 준비한다.
- 법률 문구는 출시 전 별도로 검토한다.

## Confirmed Policy

- 이용약관, 개인정보처리방침, 배송 정책, 취소/환불 정책은 고객 메뉴에서 접근 가능해야 한다.
- 푸터에도 주요 정책 페이지 링크를 제공한다.
- 회원가입 또는 첫 소셜 로그인 완료 시 이용약관과 개인정보처리방침 동의를 받는다.
- 주문서에서는 checkout/payment group마다 1개의 통합 확인 체크박스를 둔다.
- 주문서 통합 확인 문구는 다음 내용을 포함한다.
  - 주문 상품
  - 결제 금액
  - 배송지
  - 배송 정책
  - 취소/환불 정책
  - 결제 후 공급처 품절 가능성
  - 품절 시 해당 배송그룹 주문 금액 환불 안내
- 주문서 통합 확인 체크박스를 선택하지 않으면 결제 요청을 진행할 수 없다.
- 상품 상세와 주문서 모두에서 결제 후 공급처 품절 가능성과 품절 시 해당 배송그룹 주문 금액 환불 정책을 고지한다.
- checkout/payment group 생성 시점에 고객이 확인한 정책 버전과 확인 시각을 기록한다.
- 정책 페이지는 버전과 시행일을 가진다.
- MVP 고객 알림은 이메일과 주문 상세 상태 표시로 시작한다.
- 문자, 카카오 알림톡, 앱 푸시는 MVP 이후로 미룬다.
- 실제 법률 문구는 출시 전 별도 법률 검토를 거친다.

## System Impact

- 상품 상세와 체크아웃 화면에 정책 링크가 필요하다.
- 정책 페이지 라우트가 필요하다.
- 고객 메뉴와 푸터에 정책 페이지 링크가 필요하다.
- 첫 로그인 시 약관/개인정보 동의 화면 또는 모달이 필요하다.
- 주문서에는 통합 확인 체크박스가 필요하다.
- 결제 요청 API는 checkout/payment group의 주문서 확인 여부를 검증해야 한다.
- checkout/payment group 시점의 정책 버전과 확인 시각을 저장해야 한다.
- 이메일 발송 또는 발송 대기 기록이 필요하다.
