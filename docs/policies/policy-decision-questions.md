# Policy Decision Questions

이 문서는 정책을 하나씩 확정하기 위한 질문 목록이다.

## Step 1: Account

1. 비회원 주문을 허용할 것인가? Confirmed: 허용하지 않는다.
2. 로그인은 이메일/비밀번호로 시작할 것인가? Confirmed: 고객 로그인은 이메일/비밀번호를 제공하지 않는다.
3. 소셜 로그인은 MVP에 포함할 것인가? Confirmed: 카카오, 구글, 네이버만 제공한다.
4. 관리자 계정은 수동 생성으로 충분한가? Confirmed: DB에 등록된 소셜 계정만 관리자 권한을 가진다.

## Step 2: Catalog And Inventory

1. 실제 재고 수량을 관리하지 않는다는 전제를 확정할 것인가? Confirmed: 실제 재고 수량은 관리하지 않고 판매 상태만 관리한다.
2. 옵션 단위 품절을 허용할 것인가? Confirmed: 상품 상태와 옵션 상태를 분리한다.
3. 상품 상세는 어떤 형식으로 작성할 것인가? Confirmed: IMAGE + HTML 블록 방식으로 작성한다.
4. 상품 이미지는 최대 몇 장까지 허용할 것인가? Confirmed: 대표 1장, 갤러리 최대 10장, 상세 블록 이미지 최대 50장, 이미지당 최대 5MB.
5. 공급처 가격 변경 시 기존 결제 완료 주문은 어떻게 처리할 것인가? Confirmed: 결제 완료 주문은 결제 당시 가격을 유지하고, 상품 가격 변경은 새 주문부터 적용한다.

## Step 3: Order

1. 주문은 결제 전에 생성할 것인가? Confirmed: 결제 요청 전에 `PAYMENT_PENDING` 주문을 먼저 생성한다.
2. 결제 대기 주문은 얼마 뒤 만료할 것인가? Confirmed: 생성 후 30분 뒤 만료 처리한다.
3. 배송지 변경은 어느 상태까지 허용할 것인가?
4. 고객에게 내부 주문 상태를 그대로 보여줄 것인가?

## Step 4: Payment

1. PG는 무엇으로 시작할 것인가?
2. 결제 수단은 카드/간편결제만 허용할 것인가?
3. 무통장입금/가상계좌는 MVP에서 제외할 것인가?
4. 금액 불일치 시 자동 취소할 것인가, 수동 검토할 것인가?

## Step 5: Fulfillment And Shipping

1. 공급처 발주는 관리자 수동으로 시작할 것인가?
2. 배송비는 고정 배송비인가, 일정 금액 이상 무료인가?
3. 한 주문에 여러 공급처 상품이 섞이는 것을 허용할 것인가?
4. 배송 완료는 수동 처리할 것인가, 택배 조회 연동까지 할 것인가?

## Step 6: Cancellation And Refund

1. 공급처 발주 전 고객 직접 취소를 허용할 것인가?
2. 공급처 발주 후 취소는 관리자 승인으로 처리할 것인가?
3. 부분 품절은 전체 취소/환불로 처리할 것인가?
4. 배송 후 반품/교환은 MVP에서 어디까지 지원할 것인가?

## Step 7: Admin Operations

1. 관리자 권한을 하나로 둘 것인가, 역할을 나눌 것인가?
2. 주문 상태 변경 이력을 MVP부터 남길 것인가?
3. 환불 처리에는 관리자 사유 입력을 요구할 것인가?
4. 잘못된 상태 변경을 되돌리는 기능이 필요한가?

## Step 8: Legal And Customer Notice

1. 공급처 품절 가능성 고지는 상품 상세과 주문서 모두에 둘 것인가?
2. 주문서에서 정책 동의 체크박스를 둘 것인가?
3. 정책 버전 관리를 MVP에 포함할 것인가?
4. 고객 알림은 이메일만으로 시작할 것인가?
