# Legal Launch Checklist

실제 결제 오픈 전 법적/소비자 고지 리스크를 줄이기 위한 운영 체크리스트다. 법률 자문 대체가 아니며, 최종 약관과 개인정보처리방침 문구는 오픈 전 별도 검토한다.

## Launch Blockers

- [ ] 통신판매업 신고번호와 신고 기관을 실제 값으로 확정한다.
- [ ] 고객센터 전화번호, 이메일, 운영 시간을 실제 값으로 확정한다.
- [ ] 호스팅 제공자를 실제 값으로 확정한다.
- [ ] 계좌입금 현금 결제 기준 구매안전서비스 확보 방안을 확정한다: 은행 에스크로, 소비자피해보상보험, 또는 PG/가상계좌 재도입 중 하나를 선택한다.
- [ ] 통신판매업 신고에 필요한 구매안전서비스 이용확인증 또는 대체 증빙 확보 방법을 확인한다.
- [ ] 현금영수증 발급 방식과 담당 운영 절차를 확정한다. 1차 운영 기준은 홈택스 수동 발급이다.
- [ ] Toss live 심사와 PG 결제 계약은 B-001 Deferred로 미루며, 재도입 시 결제/구매안전서비스 안내 문구를 다시 확정한다.
- [ ] 개인정보 처리 위탁처를 확정한다: PG, SMS, 이메일, 배송조회, hosting, 이미지 저장소.
- [ ] 공정거래위원회 통신판매사업자 등록현황에서 사업자 정보 확인이 가능한지 확인한다.
- [ ] 초기 판매 상품별 안전인증, KC, 상품정보제공고시 항목을 확인한다.

## Customer-Facing Pages

- [ ] `/company`에 상호, 대표자명, 사업자등록번호, 통신판매업 신고번호, 사업장 주소, 반품 주소, 호스팅 제공자, 고객센터 연락처가 보인다.
- [ ] footer에 사업자 정보와 정책 링크가 보인다.
- [ ] `/support`에서 고객 문의 접수와 개인정보 수집·이용 동의가 보인다.
- [ ] `/policies`와 `/policies/{slug}`에서 이용약관, 개인정보처리방침, 배송 정책, 취소/환불 정책, 결제 후 품절 안내에 접근할 수 있다.
- [ ] 정책 페이지에 개발 단계 표현이나 확정되지 않은 혜택/보장 표현이 없다.

## Policy Content

- [ ] 이용약관에 서비스 이용, 주문, 결제, 품절/출고 지연 가능성, 책임 제한, 분쟁 처리 기준을 정리한다.
- [ ] 개인정보처리방침에 수집 항목, 처리 목적, 보유 기간, 제3자 제공, 처리 위탁, 파기, 권리 행사, 보호책임자를 정리한다.
- [ ] 배송 정책에 배송비 포함 기준, 배송 그룹, 발주/송장/배송완료 기준을 정리한다.
- [ ] 취소/환불 정책에 청약철회 기간, 반품/교환 접수 기간, 배송비 부담 기준, 환불 처리 기준을 정리한다.
- [ ] 결제 후 품절 안내에 공급처 품절 가능성과 배송 그룹 주문 단위 환불 기준을 정리한다.
- [ ] 계좌입금 안내에 입금 계좌, 입금자명, 입금 기한, 미입금 취소, 입금 불일치 처리, 현금영수증 요청 기준을 정리한다.

## Product Registration

- [ ] 안전모, 안전화, 안전대, 마스크, 보안경 등 보호구는 인증서, 인증번호, KC 또는 안전인증 대상 여부를 확인한다.
- [ ] 상품명, 제조사/수입자, 원산지, 재질, 규격, 사용상 주의사항, AS 기준을 상품 고시에 입력한다.
- [ ] 상세 이미지에 반품/환불/품절 정책만 묻어두지 않고, 상품 고시와 정책 페이지에도 텍스트로 고지한다.
- [ ] 공급처 상세 이미지 사용 권한과 브랜드/상표 노출 권한을 확인한다.
