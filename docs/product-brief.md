# Product Brief

## One-Liner

서비스명은 `코어블SAF`이다.

재고를 직접 보유하지 않는 단일 운영자 쇼핑몰.

## Problem

운영자는 상품을 직접 판매하고 싶지만, 물류와 출고는 공급처에 맡기고 싶다. 고객은 일반 쇼핑몰처럼 상품을 보고 결제하지만, 운영자는 주문 이후 공급처에 발주하고 배송 정보를 입력해야 한다.

이 모델에서는 공급처 품절, 출고 지연, 가격 변경 같은 운영 리스크가 발생한다. 따라서 시스템은 단순한 상품 판매 화면이 아니라 주문 이후의 상태 관리와 예외 처리까지 지원해야 한다.

## Target Users

### Customer

- 상품을 보고 구매하는 일반 고객
- 주문 상태와 배송 정보를 확인하고 싶은 고객
- 취소 또는 환불을 요청하는 고객

### Operator

- 상품을 등록하고 판매 상태를 관리하는 운영자
- 주문이 들어오면 공급처에 발주하는 운영자
- 송장번호, 품절, 취소, 환불을 처리하는 운영자

## Core Principle

결제 완료와 공급처 발주 완료는 같은 사건이 아니다.

시스템은 다음 상태를 분리해서 관리해야 한다.

- 고객 결제 상태
- 내부 주문 상태
- 공급처 발주 상태
- 배송 상태
- 취소/환불 상태

## Operating Assumptions

- 상품은 운영자가 직접 등록한다.
- 실제 재고 수량은 사이트에서 보장하지 않는다.
- 고객은 재고가 있다고 가정하고 주문한다.
- 주문 후 공급처 품절이 확인될 수 있다.
- 공급처 품절 시 고객에게 안내하고 해당 배송 그룹 주문 단위로 환불 처리한다.
- MVP에서는 공급처 발주와 송장 입력을 관리자가 수동 처리한다.

## MVP Boundary

### Customer Scope

- 고객 로그인 화면은 카카오 소셜 로그인만 제공한다.
- 기존 Google/Naver OAuth 백엔드는 계정 호환을 위해 유지한다.
- 비회원 주문과 이메일/비밀번호 로그인은 제공하지 않는다.
- 고객은 상품 목록, 상품 상세, 장바구니, 주문서, 결제, 주문 내역, 배송 상태를 사용할 수 있다.
- 고객은 출고 전 취소를 요청하고 배송 후 반품/교환/환불 클레임을 접수할 수 있다.
- 결제는 계좌입금과 관리자 입금확인만 제공한다. PG 결제는 도입하지 않는다.
- 고객에게 별도 배송비를 청구하지 않고 상품 판매가에 배송비를 포함한다.
- 여러 배송 그룹 상품을 한 번에 결제할 수 있지만, 주문은 배송 그룹별로 분리된다.

### Admin Scope

- 관리자는 DB에 등록된 소셜 로그인 계정만 접근할 수 있다.
- 관리자는 상품, 옵션, 이미지, 상품 상세 HTML/이미지 블록, 판매 상태를 관리할 수 있다.
- 관리자는 결제 완료 주문을 공급처 발주 대기 큐에서 확인하고 수동 발주를 진행한다.
- 관리자는 공급처 발주 시작, 공급처 발주 완료, 품절, 송장 입력, 배송 수동 보정, 취소/환불/반품/교환 클레임 처리를 수행한다.
- 관리자는 임의 상태값을 직접 쓰지 않고 허용된 액션과 상태 전이표를 통해서만 주문을 진행한다.
- 주문 상태 변경, 입금 불일치, 미완료 환불, 배송 수동 보정, 관리자 정정은 사유와 이력을 남긴다.

### Non-Goals

- 판매자 입점형 마켓플레이스와 판매자 정산 시스템은 만들지 않는다.
- 실제 재고 수량 관리, 실시간 공급처 재고 동기화, 공급처 자동 발주 API 연동은 제외한다.
- 비회원 주문, 이메일/비밀번호 로그인, 계정 병합은 제외한다.
- 카드, 간편결제, PG 계좌이체·가상계좌, 휴대폰 결제, 상품권 결제는 제외한다.
- 배송 그룹 주문 내부의 상품, 옵션, 수량 단위 부분 취소/부분 환불은 제외한다.
- 부분 출고, 분할 배송, 물류센터/WMS 연동은 제외한다.
- 쿠폰, 포인트, 리뷰, 고급 검색, AI 추천, 모바일 앱은 제외한다.
- 문자, 카카오 알림톡, 앱 푸시는 제외하고 이메일과 주문 상세 상태 표시로 시작한다.

### Launch-Blocking Checks

- 실제 약관, 개인정보처리방침, 배송/취소/환불 정책 문구는 출시 전 최종 검토가 필요하다.
- 사업자등록번호, 통신판매업 신고 면제 상태, 대표자, 주소, 고객센터, 개인정보 보호책임자 등 사업자 고시 정보가 실제 화면과 일치해야 한다.
- 계좌입금 구매안전서비스와 현금영수증 발급 절차가 준비되어야 한다.
- 개인정보 처리 위탁처, 제3자 제공 여부, 보존 기간, 마케팅 수신 동의 문구가 실제 운영 기준과 일치해야 한다.
- 택배사 자동 배송조회 연동 방식과 이용 조건이 확정되어야 한다.

## Success Criteria

- 고객이 상품을 선택하고 결제까지 완료할 수 있다.
- 관리자가 결제 완료 주문을 놓치지 않고 공급처 발주 대상으로 확인할 수 있다.
- 공급처 품절 시 주문을 품절 상태로 전환하고 환불 흐름으로 보낼 수 있다.
- 송장번호 입력 후 고객이 배송 상태를 확인할 수 있다.
- 주문, 결제, 발주, 배송, 환불 상태가 서로 섞이지 않는다.
